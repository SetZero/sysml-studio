SysML Studio is a graphical viewer and editor for SysML v2. Open a folder of .sysml files, browse it as a tree, read it as diagrams, change it — and every change lands as a small, reviewable patch in the files you already version.

Why SysML Studio

The modelling tool that treats your files as the model.

Graphical tools usually keep the model in a database and export text on the side. SysML Studio turns that around: the .sysml files are the truth, and the diagrams are views of them.

01

Lossless edits

An edit rewrites only the tokens it has to. Comments, doc blocks, blank lines and your formatting survive, so a diff shows exactly what changed.

02

Nothing to import

Point it at a folder. Every file is parsed with the SysML v2 grammar, names resolve across files, and the whole model is ready to browse.

03

Works with git

No project database, no binary blobs. Branch, review and merge models the way you already work with code, and keep editing in any text editor too.

Five diagram kinds

Every view laid out for you.

Select an element and the title bar offers the diagrams it can be drawn as. Boxes are placed automatically, kept apart, with edges routed around them — then drag anything where you want it.

Definition

Part, port, action and requirement definitions with their attributes and features. Composition, specialization and typing drawn as SysML draws them.

part def · port def · :> · attributes · multiplicities

Interconnection

The parts inside a definition and how they are wired: connections and flows between their ports, labelled with the names from your text.

part · connection · connect … to … · flow

Requirements

Requirements with their ids and text, and the parts that satisfy them. Trace a requirement to its design at a glance, or see what a part answers for.

requirement def · satisfy · dependency · allocate

Action flow

The steps of an action and the successions between them, top to bottom in the order they run.

action def · action · first … then …

State machine

States and the transitions between them, including loops and the way back to where it started.

state def · state · transition · entry

Editing

Change the model. Get a clean diff.

Rename, retype, add, delete, specialize, mark maturity or write a doc comment — from the tree, the inspector or a right-click on the canvas. Every dialog says what it will change before it writes a thing.

Drawing

Draw relations between two boxes.

The toolbar under each diagram adds elements and draws relations by clicking the two ends. What you draw is written as SysML text, re-parsed, and only accepted when it parses.

  • connect, flow, succession, transition
  • satisfy, dependency, allocate
  • specialization and composition
  • Undo and redo for everything, until you save
structure.sysml
#implemented
part def <'D.0'> Drone {
    doc /* A quadcopter that carries one parcel to a doorstep and back. */
    part battery : Battery;
    part fc : FlightController;
    part imu : Imu;
    part gps : Gps;
    part motors : Motor[4];
    part props : Propeller[4];
    connection mainPower connect battery.power to fc.power;
    connection imuLink connect imu.data to fc.imu;
    connection escBus connect fc.esc to motors.control;
    connection drive connect motors.shaft to props.hub;
}
Source

The text is always one click away.

Open any file in a source tab with SysML highlighting. Type freely: the file is re-parsed as you go, errors appear inline and in the problems list, and diagram edits wait until it parses again.

  • Find every usage of an element, across files
  • Jump from any box or problem to its line
  • Save writes only the files that changed

Get started

Up and running in three steps.

  1. Install the .NET 10 SDK and a JDK.

    ANTLR generates the parser at build time; if there is no JDK, the build downloads one.

  2. Clone and build.

    One solution, no other setup.

  3. Open a folder of .sysml files.

    Or start without one and pick a folder, a recent one, or the sample model.

$ git clone https://github.com/SetZero/sysml-studio
$ cd sysml-studio
$ dotnet build SysmlStudio.slnx

# open the drone sample shown on this page
$ dotnet run --project src/SysmlStudio.App -- samples/drone

# or your own model
$ dotnet run --project src/SysmlStudio.App -- path/to/model
